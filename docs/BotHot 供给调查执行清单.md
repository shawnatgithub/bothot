## 2. 调查前已知的情况（2026-11-24 核查）

- **官方市场首页**（`x.ai/bot/marketplace`）分 10 个区，每区最多展示 4 个模板，去重后 **35 个**，已预填进登记表。
- **首页没有展示全部模板**：搜索时发现 Import Bot、Sequencer 也在官方市场里，但首页没有出现。**每个分区都要点"View all"把模板补全**，实际总数会超过 35 个。
- 官方模板详情页的链接格式是 `x.ai/bot/marketplace/bots/{slug}`，例如 `pfp-bot`、`proto-bot`。
- 首页很多模板的描述里写着"不经你确认不会发送"之类的话，所以预计"已声明审批"这个副标签会很常见。
- 用网页搜索 `x.ai/bot/share` 几乎没有结果，说明**搜索引擎很少收录分享链接**。民间模板主要得靠 GitHub 和 X 站内搜索去找。

## 3. 合规边界（调查期间必须遵守）

1. **X 和 x.ai 只能人工浏览、手动记录。** 不运行任何脚本，不使用第三方抓取服务。法务咨询有结论之前，自动化手段一律不用（D20）。
2. **GitHub 可以用网页搜索或官方 Search API。**
3. **登记表里不粘贴提示词或 `SKILL.md` 原文**（§4.5 合规红线）。只填结构化标签和自己写的一句话；需要记录风险依据时，只写方向，例如"指令中出现外部 Webhook 地址"。
4. **调查期间不联系作者**，避免项目过早曝光。
5. 用普通个人账号正常浏览，不做批量点赞、关注等操作。

## 5. 各渠道执行步骤

### 渠道 A：官方市场

- [ ] 打开 `x.ai/bot/marketplace`，**逐个点每个分区的"View all"**。登记表里已有首页的 35 个和搜索发现的 2 个，把其余的补进去。
- [ ] 逐个打开每个模板的详情页，填写：
  - 详情页链接、作者、分类
  - 用到的连接器，是否含定时 Routine
  - 页面上能否看到指令和 skills 描述
  - 有没有提到自定义代码、MCP 服务或私有 skills
  - 有没有声明"发送、修改前需要用户确认"
- [ ] 记录有没有官方 **Verified** 徽章。只记录，用于对比官方标注和我们的评级有什么不同。
- [ ] **链接对应测试（10 组）**：
  - 挑 5 个官方模板，看详情页上有没有分享链接或"Share"入口；
  - 拿 5 条在 X、GitHub 上找到的分享链接，打开后看能不能确认是哪个官方模板（名称和作者都一致才算）；
  - 把结果填进"链接对应测试"表。

### 渠道 B：GitHub

- [ ] 按下面的检索词搜索。每次搜索都记一行检索日志，不管有没有结果：

  | 类型 | 检索词 |
  | ---- | ------ |
  | 代码搜索 | `"x.ai/bot/share"` |
  | 代码搜索 | `"x.ai/bot/marketplace"` |
  | 仓库搜索 | `awesome grok bot`、`grok bot templates`、`grok-bot` |
  | 话题（Topic） | `grok-bot`、`grok` |

  > 代码搜索 API 要用登录令牌，频率限制也比较严（以 GitHub 文档为准）。结果多时直接用网页搜索。

- [ ] 每找到一个 `x.ai/bot/...` 链接：
  - 是新 Bot，就在"模板登记"表新增一行；
  - 已登记过，就只在"引用登记"表加一条引用。
- [ ] 每条引用要记：仓库链接、仓库 owner、首次出现日期、owner 是不是作者本人（自引）。
  - 首次出现日期：在仓库的提交历史里找这条链接第一次加入的时间；查起来太费时，就填仓库创建日期，并标注"近似"。
- [ ] Awesome List 类仓库：整份列表里的链接都要登记，同时记下列表的 star 数和最近更新日期。

### 渠道 C：X

- [ ] 在 X 搜索的"最新"标签下检索：

  | 检索词 | 说明 |
  | ------ | ---- |
  | `"x.ai/bot/share"` | 最主要的一条 |
  | `x.ai/bot` | 范围更宽，包括官方市场链接 |
  | `"Grok Bot" template` | 没带链接的讨论 |
  | `Grok Bot 模板` | 中文社区 |

- [ ] **规模估算**：用高级搜索的 `since:` / `until:` 按周切分。从 `since:2026-08-28` 开始（模板分享功能上线日），一周一个区间，记下每周大约能看到多少条带分享链接的推文。**这一步只要估数，不用逐条登记。**
- [ ] **以下两类推文要逐条登记**：
  - 互动量较高的推文（参考：点赞加转发 ≥10）；
  - 每个新发现的 Bot，至少登记 1 条最早的推文。
- [ ] 每条记录：推文链接、发布者 Handle、发布日期、发布者是不是作者本人、指向哪个 Bot。

### 渠道 D：搜索引擎、Reddit、HN、博客

- [ ] Google 和 Bing：`"x.ai/bot/share"`、`site:x.ai/bot/marketplace`、`Grok Bot template`。
- [ ] Reddit：搜 `x.ai/bot` 和 `Grok Bot template`，相关子版块都要看。
- [ ] Hacker News：用 hn.algolia.com 搜 `x.ai/bot`。
- [ ] 博客和 Newsletter：记下所有整理过模板合集的文章。

### 渠道 E：非官方目录（竞品）

- [ ] 用 `Grok Bot templates directory`、`Grok Bot marketplace unofficial`、`Grok Bot 模板大全` 等搜索，选出最常出现的 5 个目录站。
- [ ] 按"竞品目录"表的各列逐项填写：收录数、有没有安全信息、按什么排序、更新频率、语言、能否投稿、能否作者认领、怎么变现。
- [ ] 这些目录里有、我们还没登记的 Bot，补进登记表。首次发现渠道填目录名，并尽量找到它在 x.ai 上的原始链接。

## 6. 去重规则

1. 链接先统一格式：用 `https://`，去掉 `?` 和 `#` 后面的内容，去掉末尾的 `/`，全部转成小写。格式统一后完全相同的，合并成一条。
2. 官方链接和分享链接**能确认是同一个 Bot** 的，合并成一条，分享链接填进"分享链接"列。
3. 不能确认、但名称和作者一致的，在"疑似重复"列填 Y，由产品负责人判断。

## 7. 合格标准

**硬性条件（全部满足）：**

| # | 条件 |
| - | ---- |
| H1 | 链接能公开访问（不登录或用普通账号就能打开） |
| H2 | 是 Grok Bot 模板（`x.ai/bot/` 开头的链接） |
| H3 | 页面信息足够写出一句话摘要，也能看出用了哪些连接器 |
| H4 | 不是测试、空壳、重复或明显的垃圾内容（比如名称叫 test、untitled，或者没有描述） |
| H5 | 内容不违法，没有成人、仇恨等违规内容 |

**价值门槛（满足其一）：**

| # | 条件 |
| - | ---- |
| V1 | 收录在官方市场 |
| V2 | 至少有 1 条非作者本人发的外部引用（GitHub 或 X） |
| V3 | 被至少 1 个非官方目录收录 |

> 硬性条件在"硬性条件通过"列手动填 Y/N；价值门槛和"合格"两列由表格公式自动算。
> **可能判为 ⚪ 或 🔴 的 Bot 也算合格**：它们照样收录，只是在榜单里降权或折叠。

## 8. 风险初判（不是正式评级）

调查阶段只是估算一下各类 Bot 的占比，**正式评级由审核员按 PRD §5 的规则库来做**。每个 Bot 填 3 列：

| 列 | 填 Y 的条件 | 对应的可能档位 |
| -- | ----------- | -------------- |
| 提到自定义代码 / MCP / 私有 skills | 页面描述里出现了这些依赖 | 可能 ⚪ |
| 明显风险迹象 | 要求把数据发到外部地址、索要密码或 API Key、要求向用户隐瞒操作 | 可能 🔴 |
| 高危连接器 | 发邮件、发帖、写 GitHub、金融支付、读邮箱或云盘 | 可能 🟡 |

## 9. 根据调查结果怎么做

**主判定（D17）：**

| 合格数 N | 动作 |
| -------- | ---- |
| N < 50 | **延期上线**，观察期一起顺延。产品负责人决定用什么方式补供给（扩大检索范围、公开征集投稿等） |
| 50 ≤ N ≤ 100 | **按期上线**，全部进入审计；报告标题写成《N 个公开 Grok Bot 安全体检报告》 |
| N > 100 | 按非自引外部引用数从高到低取前 100–120 个作为首批审计，官方市场模板优先（D40）；其余转入审核队列，上线后陆续审计 |

**其他指标触发的动作：**

| 指标 | 触发条件 | 动作 |
| ---- | -------- | ---- |
| 链接对应成功率 | < 80% | §4.4 改为"名称 + 作者"人工合并，别名表只存人工确认过的对应关系 |
| 有 GitHub 引用的 Bot 数 | < 20 | D25 的最大值方案会生效，在预期之内 |
| 有 GitHub 引用的 Bot 数 | < 10 | 冷启动榜区分度不够，报告产品负责人，考虑调整渠道权重或加大人工补录 |
| 可能 ⚪ 的占比 | > 40% | 首页会出现大量灰标，评估是否要在首页加"信息不足"的说明 |
| 作者 X Handle 覆盖率 | < 70% | 申诉会有更多人要走邮件核实，审核员要预留时间 |
| X 带链接推文的估算总数 | — | 拿去和抓取服务的报价对比，确认一次性抓取约 $10 的预算够不够（D8） |
| 近 7 天有新增引用的 Bot 数 | < 10 | Trending 第 15 天大概率先上简化版（D27） |
| 全部渠道去重后的 Bot 总数（含不合格的） | — | 用来判断 Phase 2 的"2,000–10,000+"目标是否现实 |
